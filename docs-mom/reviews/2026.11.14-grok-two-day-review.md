Overall assessment

This is a high-quality, disciplined two-day review. The pre-registration habit, the willingness to kill theories with evidence (the plane layout discovery on BL-29), and the clear separation of “what the numbers actually showed” from hopes are all strong. The document correctly identifies that pure sampled-CE distillation is saturating on shape rather than knowledge, and that the decode ceiling is intrinsic without a better drafter. The planned logit-KD + MTP path is the right next move.

### Strengths
- Evidence hygiene: Killing the “8 regions” theory, keeping the coherence gate and decode bar frozen, and documenting the twin-control failure are exactly what you want to see.
- Root-cause clarity on BL-29: Plane layout + sanitizer fix + exoneration of the copy path is clean. The remaining device-copy-leg gap is correctly flagged.
- Distillation diagnosis: The t1→t3 progression (loss moves, gate stays at 3/12, misses are knowledge not format) is well observed. Switching to logit-KD is the logical response.
- Stack landmine catalog: The config-form, safetensors offset, kernels/hub version, and especially the unified-RAM mmap pinning issues are documented with enough precision that the next person can avoid them.

### Concerns and risks
1. Unified-RAM wall is the current critical path. The disable_mmap=True discovery is promising, but it is still untested at full scale. If it fails or is only marginally better, the entire KD prep (and therefore t4) is blocked. Have a fallback ready (e.g., streaming teacher logits from a second process, or quantizing the teacher further before the run).

2. MTP acceptance realism. Going from 141.9 to ≥154 with a 1-layer MTP on a ~0.8B tail is aggressive. Even 85% acceptance is optimistic for a single-layer head that only sees the student’s own hidden states. You should pre-register a lower but still useful acceptance target (or a staged measurement) so a 60–70% result is not automatically treated as failure.

3. Top-k=8 for KL. On a 152k-vocab MoE teacher this is thin. The mass outside the top-8 can be large, especially on knowledge-heavy tokens. The renormalization of the tail is a reasonable engineering choice, but it weakens the signal precisely on the failure modes you care about (arithmetic, unit conversion, etc.). A small ablation (k=8 vs k=16 or k=32 on a 500-row subset) would be cheap insurance.

4. Teacher quantization noise. Using an fp8-dequantized-bf16 teacher is pragmatic, but you are now distilling against a noisy approximation of the original NVFP4 parent. If t4 still plateaus, you will not know whether the limit is the student capacity, the KD recipe, or teacher noise. Prefer the native NVFP4 teacher if memory allows once disable_mmap is proven; otherwise document the noise floor.

5. Dependency chain tightness. MTP training is blocked on the coherence gate. That is correct for quality, but it means any further delay in the KD path delays the decode-bar experiment. Parallelizing the MTP trainer smoke (on the existing t3 student, even if it only scores 3/12) would de-risk the export/serve path without violating the gate.
### Answers to the reviewer asks
- Top-k=8 sufficiency: Marginal. It is probably enough to get some movement if the KL term is alive, but it is under-powered for the exact failure categories (rare numerical tokens). Recommend at least a 500–1000 row k=8 vs k=32 dry-run before committing the full 12k prep. Storage cost of k=32 is real but not prohibitive for a one-time prep.
- fp8-dequantized-bf16 vs native NVFP4: Prefer native if you can make the memory work. The quantization noise is small in absolute terms but non-zero on the tail of the distribution—the exact place your gate is failing. If you stay with the dequantized teacher, add a short “teacher top-1 agreement on the 12 gate items” calibration check so you know how much the target itself is already wrong.
- t3 failure taxonomy: The examples you listed (arithmetic, unit conversion, spelling) are classic knowledge/precision failures, not format. I do not see evidence of format collapse in the description. The corpus-diversity branch (5b) is still worth doing later, but it should not be the first escalation.
- Realistic MTP acceptance: For a trained 1-layer MTP on a 0.8B-class tail, 60–75% acceptance on typical chat lengths is a more realistic first target than 85%. 85%+ is possible but usually requires either a deeper head, multi-token training objectives, or a stronger draft model. Pre-register 70% as the “interesting” threshold and 85% as the “clears the bar comfortably” threshold so the measurement is informative either way.

### Minor notes
- The plane-layout lesson is worth a short internal note: any future cache adoption or SharedView work should start from the actual tensor layout rather than from assumed region counts.
- The kernels==0.12.3 + hub 1.x pin is fragile; pin it in the environment file and add a one-line comment so it is not rediscovered the hard way.
- BL-28 (does park actually drop the heavy lane’s kept states?) remains important. Even if the decode bar is cleared with MTP, an incorrect park implementation will waste the memory advantage you are trying to preserve.

Bottom line: The diagnosis is solid and the planned KD → MTP sequence is the right one. The highest-leverage near-term actions are (1) prove disable_mmap at full teacher size, (2) do a small top-k ablation before the full prep, and (3) pre-register a more realistic MTP acceptance band so the decode measurement is informative. The discipline shown in the review makes the remaining risks manageable.
