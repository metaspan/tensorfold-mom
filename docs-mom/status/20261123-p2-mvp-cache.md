# P2 — MVP cache config adopted (23 Nov 2026)

## What was adopted
MVP = lane-local request-starts prompt caching on BOTH lanes
(`TF_QWEN_REQUEST_STARTS=1`) + exact re-prefill on lane switch. No
cross-checkpoint shared cache (S1 run 3 NO-GO stands).
- Canonical invocation: `experiments/mom_mvp_serve.sh` (boots both lanes,
  asserts the cache-mode registration line, fails closed otherwise).
- Regression: `tests/mom/test_cache.py` — 10 checks, all PASS on device
  (23 Nov): tokenizer identity, cache-mode registration, warm same-lane
  prefill-saved 96.5% (2B) / 96.7% (35B) with all reuse turns hit,
  cross-lane first-turn full prefill (resumed at 0, both directions).
- docs/12 addendum records the adoption + measured numbers; README journey
  table extended.

## Findings along the way
- **Tokenizer identity holds but merges are stored inconsistently** across
  the two checkpoints (2B: list of pairs; 35B: pre-joined strings). Naive
  byte comparison FAILS; normalized comparison is identical (247,587
  merges, vocab 248,044). The regression test normalizes; any future
  tokenizer guard must too. There is no standalone merges.txt in these
  checkpoints (an early hash-compare "MATCH" was comparing two missing
  files — caught and fixed).
- Boot assertion greps the process-wide line
  `registered overrides: TF_QWEN_REQUEST_STARTS=1` (mom-serve logs the
  registered override once per process, at engine load). BL-4 (enforce the
  per-lane cache mode inside mom-serve with a host test) is the real
  fix; the launcher assertion is the interim guard.
